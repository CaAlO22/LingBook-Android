# 真机测试待办（本轮导航动画改动）

模拟器（MuMu，Android 12）无法覆盖的项目，待本轮开发完成后统一在真机验证。

## 预测式返回（Android 14+，手势导航）

- [ ] 判定启发式是否准确：`SDK >= 34` + 本次 pop 由平台返回手势发起（`BackEvent.swipeEdge` 有新记录）。
  - 验证应用内返回键、三键导航返回键不会被误判为预测式返回。
- [ ] 预测手势拖动过程中：页面是否非线性缩放到约一半（越大越慢），且拖动阶段只走时间轴前 50%；松手后剩余一半是否顺畅补完。
- [ ] 预测手势提交后页面从 60% 不透明度直接消失是否有明显突兀感；取消手势是否能从半程回弹到 100% 且无残影。
- [ ] 系统层面关闭「预测性返回动画」时，是否会误走预测分支（表现为缩到 60% 后硬切）。
- [ ] 手势返回的收起点是否为“推走方向”：取起点与第二个采样点的连线，延长到手指对侧的屏幕边缘求交点，纵向超出屏幕时贴边；斜向滑动时是否像手指把页面推走。
- [ ] 轻扫（采样不足、未算出方向）时是否退回“起点关于屏幕中心镜像”的兜底终点且返回正常。
- [ ] 延迟启动预测转场（等待第二个采样点）是否造成预测动画起步可见滞后。
- [ ] 应用内返回键 / 三键导航返回键仍收向左上角返回键位置 `(0.08, 0.09)`。

## 返回事件转发（拦截平台回调读取起始边）

应用以 `PRIORITY_OVERLAY` 注册平台返回回调，记录 `swipeEdge` 后转发给 `OnBackPressedDispatcher`。

- [ ] 预测式返回的拖动 / 松手 / 取消是否与改动前一致（转发未破坏 NavHost 原生动画）。
- [ ] 未转发到应用、由系统直接处理返回时，根页面的退出应用预测动画是否未受影响。
- [ ] 返回手势从「无法返回的根页面」发起时是否仍能正常回到桌面。

## 设备圆角

- [ ] 真实圆角屏上 `Display.getRoundedCorner()` 是否返回有效半径。
- [ ] 小卡片圆角是否随缩放等比缩小，整体看起来像一块迷你屏幕。
- [ ] 页面四角是否露出窗口底色（尤其深色主题、大圆角机型）。
- [ ] 分屏 / 自由窗口模式下圆角裁剪是否异常。

## 转场锚点

- [ ] 应用内返回键的返回终点固定为归一化 `(0.08, 0.09)`（左上角返回键），在不同分辨率、状态栏高度、刘海屏上是否仍对准返回键。
- [ ] 进入起点为点击位置：在边缘点击、横屏、大屏设备上是否正常；冷启动无点击记录时回退屏幕中心是否合理。
- [ ] 系统返回手势是否向应用透传触摸坐标（当前按“不透传”处理，`NavPressAnchor` 仅依赖应用内点击）。
